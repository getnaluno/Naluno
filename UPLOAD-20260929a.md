## Calls: the caller kept ringing after an answer
A ring that an earlier call left behind in the database (the app closed or
the network dropped mid-ring, or an older version of the app) was still
shown on the receiving phone. When the same person called again, 28h kept
that old ring on screen and told the new call "busy". The receiver answered
the old ring, which nobody was on, and the caller's real call went unanswered.

Fixed:
- A newer ring from the same person always replaces the older one. If you
  were already picking up the older ring, the newer one is answered.
- Each new call clears the caller's own leftover rings first, so they stop
  showing up on the other phone.
- Answering a leftover ring with nothing to connect to closes it cleanly.
- Answer, decline and busy no longer depend on a database transaction alone.
  If the transaction fails on a weak connection, a checked write takes over.
  The rules still stop any call from going backwards.
- While a phone is ringing (in or out), it also checks the call record
  every 3 seconds. If its live listener stalls, the ring still stops when
  the other side answers, declines or hangs up.

## Bands: different vibes on different phones
Band cards and rooms are found by a number kept on the phone. Bands restored
from the phone's memory kept their old numbers, but the counter started
again on every open, so a new Band could get the same number as an old one.
Tapping it then opened the other Band, with that Band's vibe, and which one
you got depended on what each phone remembered. Also, a saved Band list
could replace the live Bands with an old copy.

Fixed: every Band gets its own number, duplicates are repaired before the
list is drawn, and real Bands always come from the database, never from an
old saved copy.
