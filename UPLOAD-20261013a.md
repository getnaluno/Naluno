# Upload — build 20261013a (Launch & Capacity)

Contains everything from 20261012b and 20261012c. If those were not uploaded,
upload only this zip.

## Order (it matters)

New sign-ups need a registration seat from the economy worker, and the new
database rules refuse a new profile without one. So the workers go first and
the rules go last. Existing accounts are never affected at any step.

### 1. Economy worker
Cloudflare → Workers → `naluno-economy` → Edit code → replace everything with
`naluno-economy-worker.js` → Deploy.
Check: `https://naluno-economy.naluno.workers.dev/health` shows `"launch": true`
and `/v1/launch/status` answers `"accepting": true`.

### 2. Both upload workers
Cloudflare → Workers → `naluno-broadcast-upload` → replace the code with
`signal-worker-index.js` → Deploy. Then the same for `naluno-signal-upload`.
Both already have `SWEEP_KEY`; it must be the same value as on `naluno-economy`
(it signs the upload reports). Check `/health` shows `"launchLimits": true`.

Recommended, once: R2 → each bucket → Settings → Object lifecycle rules →
"Abort incomplete multipart uploads" after 1 day. (The worker also cleans
abandoned uploads itself.)

### 3. GitHub (any order, `app/index.html` LAST, inside the `app` folder)
- `sw.js`, `pwa.js`
- `admin/index.html`, `js/admin-console.js`, `js/admin-launch.js` (new)
- `js/launch.js` (new), `js/auth.js`, `js/broadcast-composer.js`, `js/broadcast-core.js`,
  `js/broadcast-live.js`, `js/broadcast-space.js`, `js/broadcast-upload.js`, `js/band-list.js`,
  `js/signal-core.js`, `js/live-preview.js`, `js/trust-legal.js`, `js/calls.js`, `js/ice-core.js`,
  `js/pwa.js`, `js/circle.js`, `js/profile.js`, `js/naluno-voices.js`, `js/discover-engine.js`
- `workers/economy/*.mjs`, `naluno-economy-worker.js`, `signal-worker-index.js`
- `firestore.rules`, `MainActivity.java`
- tests (`js/*.test.cjs`, `js/discover-v3.pinned.json`, `workers/economy/*.test.mjs`)
- `UPLOAD-20261012b.md`, `UPLOAD-20261012c.md`, `UPLOAD-20261013a.md`
- `app/index.html` last

### 4. Firestore rules (last)
Firebase console → Firestore → Rules → paste `firestore.rules` → Publish.

### 5. Console, once
1. Launch & Capacity: Founding Circle is active (cap 50, registration on,
   waiting list on, today's media limits). Check the numbers, then press
   **Save registration** once: that creates version 1 and publishes it.
2. Resource guardrails: enter the budgets you want judged (leave 0 for any you
   do not). No money is filled in for you.
3. From 12c, if not done: Broadcasts → "Held only because the publisher was
   new" → Check → Release; "Older Broadcasts missing…" → Check → Restore.

### 6. Android app
Rebuild the APK if 12b/12c were not built yet (`MainActivity.java`).

## Rollback
- Rules first: republish the rules from commit da75875 (then a profile no
  longer needs a seat).
- Then re-upload the files from da75875 (`app/index.html` last) and redeploy
  that commit's `naluno-economy-worker.js` and `signal-worker-index.js`.
- Launch data (`launchConfig`, `launchPrivate`, `launchState`, `registrations`,
  `waitlist`, `launchAudit`, `launchHistory`, `launchUsage`) can stay: nothing
  old reads it.
