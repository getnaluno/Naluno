# Build 20261023d — upload

Security hardening (console lock-out + 6-digit code, the avatar injection, App
Check + abuse throttles), after a final audit against the live app. Replaces
23c — if you downloaded 23c, use this one instead. Includes everything that
differs from GitHub's current build (23b).

## What the final audit fixed in 23c before it could reach you
- **Database rule would have broken profile saves.** The app saves
  `photo: { crop: null }` for large photos, and a rule sees the whole merged
  document, so users with that stored would have had *every* later save
  refused (presence, Known, push clean-up, Callsign). The rule now allows
  empty values and only checks the photo when the photo itself changes.
- **Signup cap was too tight.** MTN/Airtel put thousands of phones behind a
  few shared addresses; 8 new accounts/hour per address would have refused
  real people. Now 300/hour by default, changeable without a code change.
- **Console could have locked you out with the right password.** When the
  worker's copy of your password is out of date, the console has always
  checked this phone's/account's copy instead. 23c stopped at the worker's
  "wrong". 23d checks your copies first, as before. The worker also now reads
  the console's last-resort account copy, so it is out of date far less.
- **Lock-out gaps closed.** Wrong passwords tried through any admin route
  (not only Unlock) now count; a console re-sending the same old password
  counts once, so it can never lock its owner out. Five wrong codes mean a
  15-minute wait for codes.
- A broken, unused leftover file (`workers/economy/console-gate.mjs`) was
  removed. Ignore it if you saw it; it named a secret the worker never reads.

## 1. Console: 3 wrong passwords, then a 6-digit code
- After **3 wrong passwords** the password alone stops working and the
  **6-digit code** is needed too. With the code you get in and are asked to
  set a new password straight away.
- The counter lives in `adminCredentials/{uid}`, which no browser can write.
- If the lock trips while the console is open, it goes back to the gate and
  asks for the code.
- **Never permanent:** no code set → a 15-minute wait instead. 5 wrong codes
  → a 15-minute wait for codes. Last resort: delete the `gate…` fields of
  `adminCredentials/<your uid>` in the Firebase console.
- **The way you log in is unchanged.**

### Where to keep the code (pick one; the worker secret wins if both are set)
**A. Worker secret with wrangler — most secure, never in the database:**
```
cd workers/economy
npx wrangler secret put CONSOLE_RECOVERY_CODE
#   type your 6 digits when asked
npx wrangler deploy
```
**B. From the console — no wrangler:** Control Centre → **Secret code** (next to
Change password) → type the 6 digits twice. Saved hashed on the worker. Use
**Secret code** with a blank entry to remove it.

Write the code down somewhere safe, apart from your password.

## 2. Avatar injection — closed at both ends
Crop values are forced to numbers and the photo address goes through an
allow-list before drawing; the database rule refuses a non-number crop when
the photo is changed.

## 3. App Check + abuse throttles
- **App Check is in, but OFF** (`RECAPTCHA_SITE_KEY = ""` in
  firebase-config.js). Tested with the real Firebase SDK: with no key, loading
  it changes nothing — same network calls, no App Check requests, no errors.
  To turn it on safely:
  1. Create a **reCAPTCHA v3** key for `getnaluno.com` (Google Cloud).
  2. Firebase console → **App Check** → register the web app with it, leave it
     on **Monitor**.
  3. Paste the **site** key (never the secret) into `RECAPTCHA_SITE_KEY`,
     upload, watch the monitor page for a few days.
  4. Then switch App Check to **Enforce** in the console (reversible).
- **New accounts per network address: 300/hour** by default. To change it,
  set the worker variable `CLAIM_IP_PER_HOUR` in Cloudflare (0 = off).

## Deploy
1. Upload the files.
2. **Deploy the economy worker** (`2.17.1-20261023d`):
   `cd workers/economy && npx wrangler deploy` — or paste the rebuilt
   `naluno-economy-worker.js` in the Cloudflare dashboard (naluno-economy).
   Add `wrangler secret put CONSOLE_RECOVERY_CODE` if you use option A.
3. **Publish the database rules:** `firebase deploy --only firestore:rules`.
   Before publishing, you can check the rule in Firebase console → Firestore →
   Rules → **Rules Playground**: an *update* of `users/<your uid>` setting
   `name` must be **Allowed** even when the stored photo is
   `{ crop: null }`; an update setting `photo.crop.xPct` to the text `"x"`
   must be **Denied**.
4. Deploy the Compass worker from 22a if you still haven't.
